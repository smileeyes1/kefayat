# KEFAYAT Ω — GEMINI KNOWLEDGE PACK

## Purpose
This pack is a **knowledge layer**, not a replacement for system instructions. It supplies structured educational knowledge, competency interpretation rules, mathematical visual safeguards, worksheet specifications, and evidence discipline for Gemini-based educational production.

## Authority model
1. Explicit user requirements and constraints have highest task-level priority.
2. The active repository control plane and protected golden contracts govern assurance behavior.
3. Source competency documents supplied by the user are treated as `USER-PROVIDED REFERENCE` unless independently verified as official.
4. Raw source content must be preserved; normalization or summaries must never silently replace it.
5. When source text conflicts with an explicit user requirement, preserve the source as reference and follow the user's explicit requirement for the requested artifact unless a higher-priority safety or factual constraint applies.
6. Never invent curriculum requirements, competency wording, standards, citations, or official status.

## P0 Golden Render authority
For Arabic student-facing linear addition, the protected contract is:

`SEMANTIC / USER-EYE: A + B = R`

`ENGINE REQUEST: R = B + A`

Reference: `٤ + ٣ = □` ⇐ `□ = ٣ + ٤`.

Operand identities are immutable; commutativity is not permission to swap. RTL/BiDi is not the authority. The final rendered artifact seen by the student is the acceptance oracle. `02_MATH_VISUAL_CONSTITUTION.md` is the detailed active mathematical safeguard.

## Core evidence chain
`SOURCE → COMPETENCY → LEARNING OUTCOME → OBSERVABLE PERFORMANCE → ACTIVITY → EVIDENCE → ASSESSMENT → ASSURANCE`

## Retrieval/use rule
When generating an educational artifact, retrieve the narrowest relevant knowledge first, then apply the normative safeguards in this pack. A stale/historical duplicate never overrides the active P0 contract. Do not treat the mere presence of information in a knowledge file as proof that the information is current, official, or universally applicable.

## Non-negotiable release principle
`GENERATED ≠ VERIFIED ≠ USABLE ≠ RUNTIME-QUALIFIED`

The final human-visible artifact is the acceptance target. Internal data, code, generation success, or CI success cannot override a visible defect or unproven platform behavior.
