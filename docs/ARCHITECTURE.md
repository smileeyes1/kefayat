# Kefayat / GEM Ω Architecture

## Frozen governance core
`MASTER Ω vΩ.7.4 + OAC-01 + OAG-01`

## Layer 1 — Source of truth
Immutable raw source artifacts. No silent rewriting.

## Layer 2 — Structured knowledge
Validated competency records with stable IDs, provenance, domains, outcomes, mastery states, values, and source locations.

## Layer 3 — Curriculum graph
Relationships between grades, subjects, competencies, prerequisites, outcomes, observable performance, activities, evidence, and assessments.

## Layer 4 — Deterministic assurance
Requirement integrity, acceptance freeze, traceability, evidence sufficiency, test validity, oracle status, visual/math safety, adversarial checks, regression, and release gates.

## Layer 5 — AI assistance
AI may generate or adapt lessons, activities, questions, and feedback only within the structured knowledge and governance boundaries. AI output is not authoritative curriculum evidence.

## Layer 6 — Teacher UX
Simple workflow: grade → subject → competency → goal → lesson → assessment → assurance report.

## Layer 7 — Deployment and cost boundary
The first release is static/dependency-light and suitable for GitHub Pages. Any future Google identity/AI integration must use the user's own authorized session and must respect provider quotas, OAuth scopes, privacy rules, and terms. The architecture must not assume that a user's free quota can legally or technically be pooled into an owner-funded zero-cost service.

## Current state
The repository began empty. The application shell and governance contracts are now bootstrapped, but the exact competency dataset is intentionally not fabricated. Source recovery/population is the next data gate.
